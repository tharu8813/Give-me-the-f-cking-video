# 프로그램 점검과 도구 및 진단 개선

2026-10-22. 현재 작업 폴더의 기존 변경분을 유지한 상태에서 점검했다. 아래 결과는 소스 검토와 로컬 자동 검사를 기준으로 하며, 공개 릴리즈나 설치본에 반영했다는 뜻이 아니다.

## 점검 범위

- 큐의 추가·중복 처리·목록 저장 및 복원·선택 작업·동시 다운로드·취소·재시도.
- 영상별 설정·자막 조회와 취소·설정 저장·종료 시 진행 중 작업 정리.
- 프로세스 출력 제한·도구 검사·설치 검증·전송 재시도·취소.
- 완료 파일의 경로·형식·실제 스트림 검사와 같은 이름의 기존 파일 보존.
- 앱 업데이트의 배포 주소·크기·해시 검사·작업 중 설치 차단·목록 복원.
- 실제 WPF 창의 바인딩·최소 창 크기·가상화·키보드·모션 줄이기.

## 발견 및 수정

| 문제 | 반영한 수정 |
| --- | --- |
| 도구 이름과 설치 기술이 앞에 나와 다음 행동을 파악하기 어려움 | 준비 상태와 권장 행동을 먼저 표시. 기능별 상태는 한국어로 표현하고 기술 정보는 기본으로 접음 |
| 정상 상태에서도 도구를 새로 받는 버튼이 가장 강조됨 | 정상일 때는 링크 추가로 복귀. 재설치는 문제 해결 영역에서 제공 |
| 내부 설치 단계명과 오류 코드가 기본 안내로 노출됨 | 설치 안내를 쉬운 문장으로 변경하고 실제 오류·분류·버전 정보는 상세에 유지 |
| 도구가 빈 버전 응답을 반환해도 정상으로 표시될 수 있음 | 빈 응답은 확인 실패로 처리하고 캐시하지 않아 다음 확인에서 회복 가능 |
| FFprobe 버전 확인에 화면 전용 예외 코드가 필요함 | 공통 도구 진단에서 올바른 -version 인수를 사용 |
| 도구 위치 변경 후 이전 검사 결과가 남을 수 있음 | 위치 변경 시 결과 초기화. 이전 위치의 늦은 검사 결과도 버림 |
| 설치 중 다른 도구 폴더를 선택할 수 있음 | 도구 준비 중 폴더 변경 차단. 설치 후 설정 저장과 재검사까지 작업 잠금 유지 |
| 설정의 도구 화면도 수동 경로 입력이 우선임 | 자동 준비 화면으로 안내하고 수동 경로 설정은 접음 |
| 다운로드 실패 안내에 JavaScript·PO Token·도구 이름이 먼저 나옴 | 사용자가 할 수 있는 준비 확인·다시 받기·대기 등의 행동으로 안내 |

## 검증

- 솔루션 빌드 성공: .NET Framework 호환 타깃과 .NET 10/WPF.
- Core/엔진 검사: **116개 통과**, 실패 0개.
- WPF 검사: **224개 통과**, 바인딩 오류 0개. 진단 화면용 21개 검사를 추가했다.
- 준비 완료·누락·최소 창·상세 펼침 상태를 실제 WPF로 렌더링하고 확인했다. 이미지는 `artifacts/wpf-preview/diagnostics-*.png`에 있다.
- 실행 기록: `artifacts/diagnostics-engine-checks.txt`, `artifacts/diagnostics-wpf-checks.txt`.

NuGet 취약성 정보 서버에 연결하지 못해 NU1900 경고가 있었다. 컴파일 오류는 없었으나 이번 실행에서 최신 취약성 정보는 확인하지 못했다.

최종 재검사 중 기존 도구 설치 안정성 검사에서 임시 폴더를 설치 폴더로 이동할 때 접근 거부가 한 번 발생했다. 코드를 바꾸지 않고 WPF 검사를 단독 재실행했을 때 224개가 모두 통과했다. 잠금 원인은 확인하지 못했으며 실패 기록은 `artifacts/diagnostics-wpf-transient-failure.txt`에 보존했다. 실제 설치 환경에서 재발하면 파일 잠금·권한을 추가 조사해야 한다.

## 남은 확인

실제 YouTube 다운로드와 공식 배포처에서 도구를 새로 받는 작업, GPU 변환, 여러 DPI·다중 모니터·스크린리더의 실제 사용, 새 PC 설치·관리자 승인은 이번에 실행하지 않았다. 도구의 로컬 실행 확인은 개별 영상의 다운로드 성공이나 최신 버전 여부를 보장하지 않는다. 설치본 생성·배포·커밋·푸시는 수행하지 않았다.
