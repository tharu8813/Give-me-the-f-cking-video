# WinForms 기능 대조 및 WPF UI 안정화

점검일: 2026-10-18. 기준은 현재 저장소의 WinForms 안정판 소스와 WPF다. 원래 WPF 지시서의 체크리스트와 별도로, 안정판에서 사용자가 실제로 할 수 있던 작업을 대조했다.

## 안정판에 있고 WPF에 빠졌거나 축소된 기능

| JSON/TXT 목록 파일 드롭 | 목록 파일을 끌어 넣어 가져오기 | 이번에 복원. 기존 파서·2MB 제한·중복 방지 경로를 재사용 |
| Ctrl+N으로 URL 추가 진입 | URL 추가창 열기 | 이번에 URL 입력란으로 포커스 이동 복원 |

핵심 다운로드, 여러 URL, 중복 방지, 저장 폴더, 영상/오디오 형식, 동시성, 비트레이트, AVI/FLV GPU 인코더, 제한된 자동 복구, 전체·개별 취소, 실패 재시도, 로그는 공유 엔진과 WPF에서 제공한다. WPF는 진행 중 추가된 URL을 다음 시작 대상으로 대기시킨다.

WinForms 설정 가져오기는 사용자 요청으로 앞선 작업에서 삭제한 WPF 기능이다. 안정판 대비 복원 대상에 포함하지 않는다. 큐 검색과 라이트 테마 선택은 현재 안정판에서도 제공하는 기능으로 확인되지 않아, 안정판에서 잃어버린 기능으로 세지 않았다.

## 재현하고 수정한 UI 문제

1. **창 닫기 중복 실행으로 예외 발생.** 닫기를 연속으로 호출하면 두 정리 경로가 실행되어 `The CancellationTokenSource has been disposed` 예외가 났다. 정리 중에는 다음 닫기를 보류하고 정리를 마친 뒤 한 번만 실제 종료한다.
2. **패널이 닫히기 전에 내용이 먼저 사라짐.** Panel 값이 빈 문자열이 되면서 ContentControl 내용이 제거됐지만, 바깥 패널은 닫힘 애니메이션 중이었다. 표시할 패널 내용과 열린 상태를 분리해 닫는 동안 내용을 유지한다.
3. **hover 뒤 비활성 버튼이 활성처럼 보임.** 버튼 자체의 Opacity 애니메이션이 비활성 스타일의 0.38을 덮어썼다. hover/press 피드백을 버튼 내부 Border에 적용해 비활성 상태 표현을 보존한다.
4. **외부 URL 추가가 작성 중인 입력을 지움.** URL 추가 공통 함수가 입력란까지 비웠다. 입력란은 해당 입력의 제출 명령에서만 비우고, 드롭·파일 가져오기는 작성 중인 내용을 보존한다.
5. **Escape 한 번에 실패창과 뒤의 설정 패널이 모두 닫힘.** 가장 위의 창만 닫도록 바꿨다. 포커스 복원도 공통 상태 변경 경로에서 처리한다.
6. **설정/실패창을 열어도 루트 드롭 처리기가 큐를 변경함.** 작업 영역이 비활성 상태이면 드롭을 거부한다.
7. **여러 URL 입력이 한 줄 높이 안에서 가려짐.** 입력 높이를 최대 72까지 늘리고 세로 스크롤을 제공한다.
8. **초기 창이 작은 화면의 작업 영역을 넘을 수 있음.** 기본값을 1180×720, 최소 900×600으로 줄이고 시작 시 실제 작업 영역에 맞춘다. 더 작은 작업 영역에서는 최소 크기도 함께 제한한다.
9. **기술용 패널 이름과 취소 아이콘의 의미가 불명확함.** Settings/Diagnostics/About 대신 한국어 제목을 표시하고, 취소 버튼의 일시정지 모양을 중지 모양으로 바꿨다.
10. **메뉴를 열면 큐 배경이 흰색으로 변경됨.** 비활성 ListBox의 기본 템플릿이 배경을 `#181D21`에서 `#FFFFFF`로 바꿨다. 배경색을 유지하는 공통 ListBox 템플릿을 적용했다. 스크롤·가상화는 유지하고 설정/진단/정보 메뉴 및 실패창에서 실제 렌더링 표면 색을 검사한다.

1~5번의 수정 전/후 실행 결과는 작업 폴더 `artifacts/wpf-ui-check/before.txt`, `after.txt`에 남겼다. 이는 실제 WPF 윈도우를 화면 밖에서 띄우고 이벤트·상태를 반복한 검사다. 외부 영상은 내려받지 않았다.

배경색 문제의 수정 전/후 결과는 `artifacts/wpf-ui-check/menu-background-before.txt`, `menu-background-after.txt`에 남겼다. 수정 후에는 활성·비활성 모두 `#181D21`이다.

## 제거한 부분

- 메인 화면의 큰 홍보 문구, 앱 정보의 중복 화살표와 영문 홍보 문구.
- 실제 어셈블리 버전 표시와 중복되는 하드코딩 `PV.01`.
- 작은 창의 빈 큐 안내를 밀어내던 큰 화살표 장식.
- 참조가 없는 `MotionEase`, `PressedBrush`, `PanelPadding`, `PanelRadius`, `PageTitle` 리소스.
- ViewModel에서 읽지 않는 SettingsStore 필드와 중복 포커스 호출.
- 사용하지 않는 햄버거 버튼과 화면·창·제품명의 Preview 표기. 창과 사이드바는 저장소의 기존 icon.ico 사용.

사용자 파일이나 미디어를 삭제하는 정리는 수행하지 않았다. 제거 대상은 WPF 표시 요소와 참조를 확인한 미사용 코드다.

## 검증 범위와 남은 작업

회귀 검사는 접힌 ComboBox의 실제 표시, 모션 변경 후 실패창 재진입, 가상화, 대량 추가 집계, 취소, 목록 저장 실패 보존에 더해 패널 반복 전환, 닫기 중복 호출, hover/비활성 상태, Escape 계층, 파일 드롭, 패널 뒤 드롭 차단, 입력 보존·스크롤을 확인한다.

| 이번 검증 | 결과 |
| --- | --- |
| 전체 솔루션 Debug 빌드 | 성공 |
| WPF 및 검사 프로젝트 Debug / Release 빌드 | 성공, 경고 0/오류 0. Release는 별도 산출물 경로 사용 |
| 기존 WinForms/Core/Engine Debug 회귀 검사 | 91 passed, 0 failed |
| WPF Debug / Release 회귀 검사 | 각각 81개 통과, 바인딩 오류 0 |
| 화면 직접 확인 | 최소 크기의 빈 큐·목록, 설정 5개 탭, 영상별 설정과 자막, 앱 정보 PNG 확인 |

최신 검사 로그는 작업 폴더 `artifacts/wpf-ui-check/features-debug.txt`, `features-release.txt`, `legacy-tests.txt`에 남긴다. 화면은 `artifacts/wpf-preview`에 생성된다.

실제 YouTube/CDN, 도구 설치·업데이트, GPU, 실물 키보드·마우스 조작, 서로 다른 DPI/다중 모니터의 이동, 프레임 시간, 다른 PC의 배포 실행은 이번 검사에서 검증하지 않았다. 이 문서의 기능 대조는 소스 경로를 확인한 결과이며, 누락 기능을 모두 복원했다는 뜻은 아니다.

영상별 옵션·품질/FPS, 자막, 목록 옵션 보존, URL 작업은 이번에 복원했다. 설정은 일반·다운로드·형식·고급·도구의 5개 탭으로 분류하고, 공통 ScrollViewer에 180ms 보간을 적용했다. 큐는 픽셀 단위 Recycling 가상화를 유지하며, Windows 애니메이션 비활성화와 모션 줄이기에서는 즉시 스크롤한다. 스크롤바 조작과 키보드 조작 시 진행 중인 휠 애니메이션을 중단한다.

남아 있는 안정판 기능 차이는 Chrome 탭 가져오기, 앱 자동 업데이트, 도구 설치/업데이트, 앱 내 영상 재생, 다중 선택 취소·제거와 Delete, 설정 기본값 복원·파일명 샘플·미저장 확인이다. 모두 복원했다고 간주하지 않는다.
