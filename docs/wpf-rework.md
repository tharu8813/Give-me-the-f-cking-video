# GMTFV 작업 공간 리워크

설계 기준일: 2026-10-18. 이 문서는 구현 전 분석과 설계, 구현 후 검증을 구분한다.

## 분석

- Core(net472/net10.0), DownloadEngine(net472/net10.0-windows), WinForms는 유지한다. WPF는 IDownloadBackend를 통해 비동기 엔진을 사용하며 취소, 큐 슬롯, 검증/복구는 이미 구현되어 있다.
- 기존 레일/입력/테이블/하단 버튼 구조에서는 형식·화질·저장 위치가 숨겨져 첫 다운로드에 설정 화면 왕복이 필요하다. 썸네일보다 행의 버튼들이 강하고, 실패 상세는 원인과 다음 행동보다 로그를 먼저 노출한다.
- MainWindowViewModel은 작업 수명, 큐, 설정, 파일 대화상자, 패널을 함께 관리한다. 엔진을 옮기기보다 도구 준비와 모션을 독립 서비스로 분리한다. 기존 영상별 옵션/자막 ViewModel은 재사용한다.
- 현재 모션은 동일한 세로 이동/페이드이고, 설정 변경이 실행 중인 무한 애니메이션을 즉시 정지하지 않는다. 가상화 재활용 시 재등장과 실제 신규 추가를 구분해야 한다.
- 기능 차이는 `wpf-feature-parity.md`의 소스 대조표를 기준으로 다시 검증한다. 기존 설정 JSON, 목록 JSON/TXT 및 WinForms 목록 호환을 유지한다.

## 새로운 UX / 디자인

콘셉트: **미디어 작업대**. 따뜻한 흑연색, 종이색 텍스트, 구리색 강조. 상단 탐색과 넓은 콘텐츠 목록으로 작업 도구보다 영상이 먼저 보이게 한다. 한국어 본문은 시스템 한글 글꼴, 수치에는 고정폭 글꼴을 쓴다. 외부 글꼴/아이콘 패키지는 추가하지 않는다.

1. 링크 입력/드롭 → 즉시 큐 삽입과 정보 확인 → 같은 화면에서 영상/오디오·형식·품질·폴더 확인 → 다운로드.
2. 영상별 옵션과 자막은 행의 명시적 버튼에서 연다. 공통값 상속과 개별 지정은 유지한다.
3. 완료 행은 실제 출력 경로와 파일/폴더 열기를 제공한다. 실패는 사용자 언어의 원인·다음 행동을 먼저 표시하고 기술 상세는 펼친다.
4. 전체 진행은 완료 **항목 수**다. 파일 크기를 모르는 큐에 바이트 기반 전체 %/ETA를 만들지 않는다. 개별 %는 엔진 값이 있을 때만 표시한다.
5. 고급 설정과 도구 관리는 보조 패널. 도구 준비는 사용자 클릭으로 시작하고 검증된 새 묶음을 별도 폴더에 설치한 뒤 경로를 전환한다. 공유 실행 파일을 덮어쓰지 않는다.

## 모션 계약

- 반응 120ms, 상태 240ms, 공간 전환 320ms. 하나의 속성에는 교체 애니메이션만 사용한다. 빠른 역전은 현재 화면 위치에서 이어지고 오래된 완료 콜백은 무효화한다.
- 패널은 옆에서 진입하고 작업 공간은 깊이/가로 이동으로 반응한다. 모달과 토스트는 별도 역할을 가진다.
- 다운로드 여정은 정보/대기/받기/후처리/완료의 실제 상태를 연결한다. 병합·변환·검증은 퍼센트를 추정하지 않는다. 실패·취소는 진행 도중 정지한 상태로 남긴다.
- 목록은 실현된 소수 행만 등장/재배치한다. 스크롤 재활용에 애니메이션을 반복하지 않고 대량 변경은 제한한다. RenderTransform/Opacity 중심, 지속적인 레이아웃 크기 애니메이션은 사용하지 않는다.
- Windows 애니메이션 설정과 앱 모션 줄이기를 모두 준수하며 설정 변경 시 진행 중 움직임도 즉시 정리한다. 입력은 퇴장 시작 시 차단하고 완료 후 Visibility를 접는다.

## 변경 범위 / 회귀 위험

Views, Themes, Motion/큐 모션, 표시용 ViewModel 속성, 도구 준비 서비스, 연결된 명령·설정 바인딩·테스트·문서를 함께 변경한다. Core/Engine/WinForms 실행 경로와 사용자 미디어는 수정하지 않는다. 특히 취소/닫기 수명, 영상별 옵션 상속, 드롭·키보드, 가상화, 비활성 목록 배경, 설정 파일 호환을 기존 검사와 함께 확인한다.

## 구현 결과

### 화면과 기능

- 레일을 제거하고 상단 탐색, 링크 작성 영역, 공통 빠른 옵션, 썸네일 목록, 완료 항목 집계로 화면을 재구성했다. 기본 창 1220×800, 최소 900×660이며 실제 작업 영역이 더 작으면 시작 크기와 최소 크기를 함께 제한한다.
- 영상/오디오·형식·화질 또는 비트레이트·저장 위치가 메인 화면에 있다. 최고 화질을 숫자 0 대신 사용자 언어로 표시한다. 공통 설정 변경은 상속 항목만 갱신하고 실행 중 요청 스냅샷은 보존한다.
- 기존 영상별 해상도/FPS·형식·자막 조회/저장·URL 작업을 유지하며 상세 패널에 썸네일을 추가했다.
- 완료 항목은 실제 엔진 반환 경로와 파일 열기/탐색기 선택 명령을 제공한다. 파일이 이동/삭제되면 오류 안내를 표시한다. 파일을 임의로 삭제하지 않는다.
- 실패 분류를 제목과 사용자 조치로 표시한다. 기술 상세는 접혀 있으며 수동 재시도·도구 확인으로 연결한다. 자동 복구 여부와 시도 횟수는 기존 엔진 정책을 따른다.
- Ctrl/Shift 다중 선택, 선택 작업 취소·목록 제거, Delete, 선택 작업 표시줄을 추가했다. 제거 전 선택 항목을 복사해 목록 변경 중 선택 컬렉션이 바뀌어도 안전하게 처리한다.
- 설정 기본값 복원, 파일명 미리보기, 저장됨/변경됨 표시를 추가했다. 저장 형식과 저장 경로는 그대로다. 설정 저장은 고유 임시 파일을 통한 교체이며 실패 시 기존 데이터와 원본 경로를 보존한다.
- 처음 실행할 때 도구 버전/누락 상태를 비동기로 확인한다. 준비 버튼은 실제 다운로드 작업이나 영상 설정 작업이 있을 때 비활성화된다. 앱의 모션 줄이기는 다운로드 중에도 변경할 수 있다.

### 통합 모션

`Motion.cs`가 반응/상태/공간 전환 토큰과 취소·역전·설정 변경을 담당한다. 스크림은 투명도, 보조 패널은 가로 이동, 상세/실패는 크기와 위치, 작업 공간은 깊이로 역할을 나눴다. 같은 속성의 클록은 교체하고 전환 세대 번호로 오래된 완료 콜백을 차단한다.

`QueueMotion.cs`는 현재 생성된 최대 32개 컨테이너만 위치를 기록하고, 추가·제거 전후 위치 차이를 RenderTransform으로 연결한다. 새 항목은 제한된 Stagger로 진입하며 12개를 넘는 일괄 변경에서는 생략한다. 스크롤 재활용은 등장 효과를 실행하지 않는다. 선택 도구는 고정 높이 헤더 안에서 전환하여 목록 위치와 높이를 바꾸지 않는다.

`DownloadJourney.cs`는 실제 상태에서 계산한 정보/준비/다운로드/후처리/완료 단계의 연결선·노드·이동 표식을 그린다. 병합/변환/검증과 재시도는 실제 상태 이름을 유지한다. 실패와 취소는 중단된 위치에서 멈추고 색과 텍스트로 구분한다. 서버가 주지 않은 ETA나 바이트 진행률을 만들지 않는다.

버튼 hover/press/release, 토글 이동, 입력 포커스, 썸네일 다운로드 완료 시의 진입, 완료 항목 진행률을 공통 동작으로 처리한다. 불확정 진행률은 숫자 없이 제한된 표시를 사용한다. Windows 또는 앱 모션 줄이기 변경 시 skeleton/불확정 표시/스크롤/토글/목록 이동/패널을 즉시 정리한다. 커스텀 렌더링은 짧은 단계 전환에만 사용하며 지속적인 프레임 이벤트 구독은 없다.

### 도구 설치의 경계

[yt-dlp 공식 릴리스](https://github.com/yt-dlp/yt-dlp/releases), [Deno 공식 릴리스](https://github.com/denoland/deno/releases), [Gyan FFmpeg 빌드](https://www.gyan.dev/ffmpeg/builds/)를 사용한다. Gyan은 FFmpeg Windows 바이너리 배포처이며 FFmpeg 프로젝트 자체의 바이너리 서명으로 표현하지 않는다.

GitHub 자산의 SHA-256 digest 또는 Gyan 체크섬이 없거나 다르면 설치하지 않는다. 응답과 압축 해제 크기를 제한하고 압축 파일에서 정해진 실행 파일만 꺼낸다. 압축 경로를 그대로 파일 시스템 경로로 사용하지 않는다. 배포 고지도 보관한다. 검증 후 버전 명령을 실행하고 Deno 호환성을 확인한다.

`%LocalAppData%/GMTFV.Preview/Tools/bundle-<GUID>`에 새 묶음을 만든 후 설정을 저장하고 경로를 전환한다. 실패/취소 시 준비 중인 GUID 폴더만 정리하며 공유 폴더와 이전 묶음은 건드리지 않는다. 설정 저장에 실패하면 기존 설정 경로를 유지한다. 다운로드는 사용자가 버튼을 눌러 시작한다. 준비 성공 시 화면에 안내한 대로 현재 설정도 함께 저장한다.

업데이트마다 이전 묶음을 보존하므로 디스크 사용량은 늘어난다. 자동 정리와 같은 버전 중복 방지는 후속 작업이다. SHA-256은 배포처가 제공한 값과의 일치를 확인하며 별도의 서명/공증 검증을 추가한 것은 아니다.

기본 Release 폴더는 실행 중 앱이 DLL을 잠그고 있어 마지막 전체 솔루션 갱신이 실패했다(`rework-solution-release.txt`). 해당 앱을 종료하지 않고 `artifacts/rework-release`로 WPF/Core/Engine/테스트를 분리 빌드했다. WinForms Release 빌드와 회귀 검사는 별도로 성공했다. NuGet 감사는 격리 빌드에서 끈 상태이며 새로운 취약성 감사를 수행한 것으로 간주하지 않는다.

네트워크 검사는 샌드박스 DNS/루프백 차단을 확인한 뒤 허용된 실행 환경에서 수행했다. 기존 yt-dlp 테스트 영상 `BaW_jenozKc`는 서비스에서 사용할 수 없다는 응답을 받아 공개 영상의 **메타데이터 조회**로 바꿨다. 실제 YouTube 영상 파일의 다운로드 성공을 주장하지 않는다. 서명된 스트림 URL은 결과 요약에 기록하지 않았다.

## 미검증과 후속 우선순위

1. **WinForms 기능 차이:** Chrome 확장 연동, 앱 자동 업데이트, 앱 내 영상 재생은 여전히 WPF에 없다. 제공한 것처럼 버튼을 추가하지 않았다. 기존 WinForms 구현은 보존한다.
2. **실제 환경:** YouTube 영상 파일 다운로드·실서비스 실패율, 실제 자막 CDN, GPU 인코더/드라이버, 다른 PC의 ZIP 실행, 장시간 연속 사용을 검증하지 못했다. 로컬 실제 도구의 13개 형식 검사와 구분한다.
3. **모션/성능:** 물리 디스플레이의 60FPS, GPU 프레임 시간, 다양한 DPI·다중 모니터, Windows 모션 설정의 실제 OS 전환, 스크린리더와 실물 키보드/마우스 검증은 남아 있다. dispatcher 표본은 입력 처리 여부를 보는 보조 자료다. 최종 Debug는 18회/평균 24.4ms/최대 32.0ms, Release는 18회/평균 24.4ms/최대 33.2ms였으며 디스플레이 FPS 수치가 아니다. 장시간 메모리/썸네일 부하 프로파일링도 후속 작업이다.
4. **설정/목록:** 수동 JSON/TXT 목록 저장/복원은 유지한다. 세션 자동 저장, 앱 종료 시 미저장 설정 확인은 추가하지 않았다. 저장 상태를 명시하고 기존 설정 파일을 보존한다.
5. **도구:** 실제 전송 중 취소·프록시/백신/보호 폴더·여러 앱 동시 실행의 현장 검증, 이전 묶음 정리 정책과 업데이트 버전 비교를 보완해야 한다. 손상/해시 누락/비공식 주소/압축 경로/취소 경계는 오프라인 검사로 확인한다.

이 결과는 WPF 리워크의 구현과 확인 가능한 검증 결과다. 모든 기능 차이가 해소된 안정판 전환이나 모든 최종 품질 질문의 실환경 검증 완료를 의미하지 않는다.

검토용 배포본은 `artifacts/GMTFV-Rework.zip`이다. 압축을 풀고 `GMTFV.Wpf.exe`를 실행하며 .NET 10 Desktop Runtime이 필요하다. ZIP의 앱/엔진/JSON 런타임/라이선스 포함을 검사했다.

## 후속 수정: 선택 시 목록 이동 / 순서와 번호

- 원인: 다중 선택 도구가 별도 Auto 행으로 나타나며 목록 높이를 64px 줄였고, `QueueMotion.Resized`가 전체 목록의 위치를 다시 보간했다. 실제 창의 선택 전후 표본에서 최대 63.63px 이동을 재현했다 (`artifacts/queue-selection-before.txt`).
- 수정: 기존 목록 헤더를 QueueView로 모으고, 동일한 40px 높이 안에서 기본 도구와 선택 도구만 전환한다. 전체 목록의 SizeChanged 위치 애니메이션을 제거했다. 컬렉션 추가/제거/이동에 대한 행 모션과 가상화는 유지한다. 수정 후 선택 중 목록 위치/높이 변화는 각각 0px이다 (`queue-selection-after.txt`).
- 순서: 선택한 항목의 위/아래 버튼, 우클릭 메뉴, Alt+↑/↓. 다중 선택의 내부 순서와 선택 상태를 유지한다. 다운로드/도구 준비/제거 중에는 순서를 바꾸지 않는다. Esc 또는 선택 해제 버튼으로 일반 목록 도구를 다시 표시한다.
- 번호: 항목의 현재 위치를 01부터 표시한다. 추가/이동/제거 시 영향을 받는 범위만 갱신하며, 재활용 컨테이너에서도 실제 번호를 표시한다. JSON/TXT의 기존 배열 순서로 저장하므로 저장 형식 변경 없이 순서가 복원된다. 기존 파일명 템플릿의 다운로드 순번 규칙은 변경하지 않았다.
- 검사: 선택 중 프레임별 위치, 경계의 버튼 비활성화, 연속·비연속 다중 선택 이동, 빠른 반복 이동, 저장/복원, 요청 생성 순서, 실행 중 잠금, 삭제 후 재번호, 1,000개 가상화 목록의 마지막 번호 표시. 새 화면은 `artifacts/wpf-preview/queue-order.png`.
- 최종 결과: Debug/Release 빌드 성공(경고·오류 0), 각각 129개 WPF 검사 통과 및 바인딩 오류 0. 두 구성 모두 선택 중 위치/높이 변화 0px이다 (`artifacts/queue-wpf-debug.txt`, `queue-wpf-release.txt`). 다운로드 요청 검사는 대역 백엔드이며 실서비스 다운로드 검사가 아니다. 실물 마우스·키보드 조작은 미검증이다.
