# UI/UX 점검 및 개선

2026-10-22. 기존 미커밋 변경을 보존하고 WPF 화면·공통 컨트롤·키보드 동작을 점검했다. 다운로드 엔진, 설정 파일 형식, 배포 버전은 이번 작업에서 변경하지 않았다.

## 수정한 문제

| 문제 | 수정 |
| --- | --- |
| 최소 창에서 모드·형식·화질이 한 줄을 차지해 저장 위치가 거의 보이지 않음 | 영상/오디오 선택을 입력 영역 상단으로 이동. 저장 위치에 남은 폭을 배정하고 긴 경로는 버튼 내부에서 줄임. 전체 경로 툴팁 유지 |
| 목록 요약이 가로 StackPanel이라 폭이 부족해도 계속 늘어날 수 있음 | 제목·개수는 유지하고 작업 중 요약만 가용 폭 안에서 줄임. 선택 도구 모음은 같은 줄을 유지하여 선택 시 목록이 이동하지 않음 |
| 설정이나 영상별 옵션을 닫으면 항상 URL 입력으로 돌아가 키보드 작업 맥락을 잃음 | 원래 포커스를 기억해 복귀. 중첩 오류 창을 닫으면 열린 패널로 돌아가며, 원래 항목이 제거되었으면 URL 입력으로 복귀. 명령 활성 상태 갱신 후 포커스 처리 |
| 원본 오디오 등에서 비활성화된 옵션의 설명을 확인하기 어려움 | 공통 버튼·콤보박스에서 비활성 상태에도 기존 툴팁 제공 |
| 정상 상태에도 빨간 `실패 0개`가 표시됨 | 실패가 있을 때만 경고 개수 표시 |
| 오류 창에서 `닫기`가 복구 행동보다 강조됨 | `다시 시도`를 강조하고 실행할 수 없는 경우 안내 툴팁 제공 |

## 검증 결과

- 검증용 출력 경로에서 전체 솔루션 Release 빌드 성공: 오류 0개.
- WPF 자동 검사 **255개 통과**. 이번 UI/UX 검사 31개 포함.
- Core/다운로드 엔진 자동 검사 **116개 통과**, 실패 0개.
- 900×660, 1050×700, 1220×800 창에서 옵션·경로·선택 도구 모음의 실제 배치 검사.
- 최소 창에서 선택하지 않은 목록의 완전한 두 줄 유지, 1,000개 항목 가상화, 설정·오류·영상별 옵션의 포커스 복귀 검사.
- 선택 애니메이션 도중 목록 위치 변화 **0.00px**, 높이 변화 **0.00px**. WPF 바인딩 오류 없음.
- 실제 WPF 렌더링 이미지 확인: `artifacts/ui-ux-preview/queue-900.png`, `selection-900.png`, `original-audio.png` 및 기존 `artifacts/wpf-preview/` 화면.

기본 출력 폴더의 실행파일/DLL에 파일 잠금이 발생하여 별도 출력 폴더를 사용했다. NU1900 경고로 최신 NuGet 취약성 정보는 확인하지 못했다.

```powershell
dotnet build GMTFV.slnx -c Release --no-restore -m:1 -nr:false -p:UseSharedCompilation=false -p:OutDir="$PWD/artifacts/ui-ux-build/"
& ./artifacts/ui-ux-build/GMTFV.Wpf.Tests.exe
& ./artifacts/ui-ux-build/GMTFV.Tests.exe
```

실행 기록은 `artifacts/ui-ux-isolated-solution-build.log`, `artifacts/ui-ux-wpf-full.log`, `artifacts/ui-ux-engine-checks.log`에 있다. UI/UX 검사만 실행하려면 WPF 검사 실행파일에 `--ui-ux-check`를 전달한다.

## 확인하지 않은 범위

실제 YouTube 다운로드, 여러 DPI·다중 모니터·스크린리더 실사용, 새 PC 설치는 확인하지 않았다. 화면 데이터는 격리된 테스트 픽스처이며 실제 다운로드 진행률이나 도구 준비 상태의 증명이 아니다. 이 문서는 설치본 생성·배포·커밋·푸시 전의 UI/UX 검증 기록이며, 이후 패키징과 배포 안내는 [4.0.1.0 릴리즈 안내](release-4.0.1.0.md)를 참고한다.
