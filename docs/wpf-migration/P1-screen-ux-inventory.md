# P1 — 화면 및 UX 기준선

## 화면 목록

| 화면 | 현재 역할 | WPF 이관 방향 |
| --- | --- | --- |
| 메인 (`MainForm`) | URL 추가, 목록, 다운로드 큐, 전체/개별 진행 상태, Chrome 확장 안내 | 단일 작업 공간. 가상화 목록과 고정 작업 패널로 재구성한다. |
| URL 추가 (`AddURL`) | 단일 YouTube URL 입력 | 메인 화면의 인라인 입력 또는 작은 모달로 단순화하되, 현재 검증을 유지한다. |
| 설정 (`Setting`) | 출력 형식·경로·파일명·GPU·오디오·동시성, 목록 가져오기/내보내기 | 항목을 기본/고급으로 묶고 저장 전 변경 사항을 명확히 보여 준다. |
| 영상 상세 (`VideoInfoForm`) | 제목/설명/URL 및 자막 조회·저장 | 읽기 쉬운 상세 패널과 명확한 자막 상태를 제공한다. |
| 가져오기 진행 (`ImportProgressForm`) | 목록 불러오기 수량·진행 표시 | 병렬 처리 중에도 완료/실패/대기 수를 신뢰성 있게 표시한다. |
| 확인 (`VideoCheckcs`) | URL 관련 보조 확인 | 필요성을 P8에서 재평가하되, 기능을 제거하려면 동등한 흐름을 먼저 제공한다. |

## 현재 UX 기준과 개선 목표

| 영역 | 유지해야 할 장점 | WPF에서 개선할 목표 |
| --- | --- | --- |
| 빈 상태 | URL 추가 행동을 바로 안내한다. | 드래그 앤 드롭, 붙여넣기, Chrome 가져오기를 한 곳에서 발견 가능하게 한다. |
| 작업 상태 | 영상·오디오·병합·변환·완료 단계를 텍스트로 표현한다. | 단계, 퍼센트, 속도/남은 시간(가능할 때), 성공·실패를 한눈에 분리한다. |
| 목록 | 썸네일과 기본 영상 정보를 함께 보여 준다. | 많은 행에서도 부드럽게 스크롤되는 가상화 목록을 사용한다(P5). |
| 오류 | 실패 원문을 확인할 수 있다. | 사람 친화적 요약과 진단 상세를 분리하고, 다음 행동을 제시한다. |
| 설정 | 필요한 형식과 저장 위치를 한 화면에서 조정한다. | 기본 설정을 먼저 보여 주고 위험하거나 고급인 옵션은 접어 둔다. |
| 접근성 | 마우스 중심 조작 외 단축키를 일부 제공한다. | 키보드 포커스, 명확한 대비, 화면 판독기용 이름, 창 크기 조절을 기본으로 한다. |

## 화면 상태 모델

WPF 화면은 임의의 컨트롤 속성 변경 대신 아래 상태를 명시적으로 표현한다.

```text
대기 → 메타데이터 로딩 → 준비 완료 → 대기열 → 다운로드 중
                                      ├→ 성공
                                      ├→ 실패
                                      └→ 취소

다운로드 중: 영상 / 오디오 / 병합 / 변환 / 마무리
```

- 항목 상태와 전체 큐 상태를 분리한다.
- 실패한 항목은 목록에서 사라지지 않아야 하며, 오류 요약과 세부 로그에 접근할 수 있어야 한다.
- 병합 퍼센트는 FFmpeg가 보고하는 시간 기준 진행 정보가 있을 때만 확정값으로 표시한다. 정보가 없으면 불확실한 숫자를 만들지 않고 `병합 중` 상태로 표시한다.

## P4~P8 디자인 원칙

1. 사용자의 다음 행동(URL 추가 또는 다운로드 시작)을 가장 눈에 띄게 둔다.
2. 색상만으로 상태를 구분하지 않고 아이콘·텍스트·진행 막대를 함께 쓴다.
3. 다운로드 중에는 목록의 레이아웃이 흔들리지 않도록 행 높이와 상태 영역을 안정적으로 유지한다.
4. 빠르게 갱신되는 진행 정보는 UI 갱신을 조절해 스크롤과 입력 반응성을 지킨다.
5. 모달 창은 설정 확인이나 명확한 선택에만 사용하고, 일반 진행 상황은 메인 화면에서 확인하게 한다.
