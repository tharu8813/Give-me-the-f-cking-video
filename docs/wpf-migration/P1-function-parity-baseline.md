# P1 — 기능 동등성 기준선

## 목적과 범위

이 문서는 GMTFV의 WinForms 버전을 WPF로 옮길 때 지켜야 할 **기능 동등성 기준**이다.

- P1은 조사·문서화 단계다. 실행 코드, 화면 동작, 배포물은 변경하지 않는다.
- 현재 WinForms 프로젝트(`src/GMTFV.WinForms/GMTFV.WinForms.csproj`, .NET Framework 4.7.2)는 계속 기준 실행 버전으로 유지한다.
- 기존에 삭제 상태인 WPF 관련 파일은 이 단계에서 복원하거나 수정하지 않는다. P3에서 별도 프로젝트를 새로 만든다.
- WPF 앱은 P2에서 분리할 공통 기능을 사용하되, 아래의 사용자 관점 동작을 모두 재현해야 한다.

## 기준 환경

| 항목 | 현재 기준 |
| --- | --- |
| UI | Windows Forms (`Start/MainForm`) |
| 대상 프레임워크 | .NET Framework 4.7.2 |
| 영상 엔진 | 설치 폴더의 `yt-dlp.exe`, `ffmpeg.exe` |
| PO Token | 설치 폴더의 `pot-provider.exe`와 localhost HTTP 공급자 플러그인 |
| 사용자 데이터 | .NET 사용자 설정 및 WebView2 사용자 데이터는 AppData 영역 |
| 외부 도구 위치 | AppData가 아닌 실행/설치 폴더. 업데이트도 이 원칙을 유지 |
| Chrome 연동 | 포트 43128의 로컬 수신 서비스로 확장이 전송한 YouTube URL을 받음 |

## 반드시 유지할 동작

| ID | 사용자 기능 | WinForms 기준 동작 | WPF 완료 조건 |
| --- | --- | --- | --- |
| F01 | 시작 준비 | 기본 저장 폴더를 준비하고, 포함 도구를 확인하며 도구 버전을 표시한다. | 도구 누락·실행 불가를 이해 가능한 상태로 알리고, 정상일 때 같은 준비 순서를 수행한다. |
| F02 | URL 추가 | 버튼, `Ctrl+V`, `Ctrl+N` 및 드래그 앤 드롭으로 URL을 입력할 수 있다. | 동일한 입력 경로와 키보드 동작을 제공한다. |
| F03 | URL 정규화·중복 방지 | YouTube URL을 정규화하고, 이미 추가했거나 추가 중인 URL을 막는다. | 같은 URL이 중복 작업으로 들어가지 않는다. |
| F04 | 메타데이터 조회 | 항목을 임시 행으로 먼저 표시한 뒤 제목, 채널, 길이, 썸네일을 채운다. 실패도 목록에서 식별 가능하다. | UI가 멈추지 않고 로딩·성공·실패 상태가 구분된다. |
| F05 | 목록 관리 | 항목 선택, 삭제, 상세 정보 확인, 빈 목록 안내를 제공한다. | 선택·삭제·빈 상태가 키보드와 마우스 모두에서 자연스럽게 동작한다. |
| F06 | 다운로드 설정 | 저장 경로, 영상/오디오, 확장자, 파일명 형식, GPU, 오디오 비트레이트, 동시 다운로드 수를 설정하고 저장한다. | 각 값의 의미와 유효성 검사가 유지되며 기존 설정을 읽을 수 있다. |
| F07 | 큐와 취소 | 설정된 동시성만큼 다운로드를 수행하고, 실행 중 닫기/취소 의도를 안전하게 처리한다. | 종료 시 실행 중인 외부 프로세스와 로컬 서비스가 정리된다. |
| F08 | 영상·오디오·병합 진행률 | yt-dlp 출력과 FFmpeg 진행 정보를 이용해 단계와 퍼센트를 표시한다. 병합은 별도 퍼센트를 보여 준다. | 개별 작업마다 현재 단계와 퍼센트가 보이고, 전체 진행 상황도 알 수 있다. |
| F09 | 결과 처리 | 성공·실패 수와 실패 원인을 알려 주며, 각 항목 상태를 유지한다. | HTTP 403, 도구 오류, 취소를 서로 구분해 읽기 쉽게 제시한다. |
| F10 | 자막 | 상세 화면에서 자막을 조회·선택·저장한다. | 자막 목록·저장 경로·실패 처리를 유지한다. |
| F11 | 목록 내보내기·가져오기 | JSON/TXT 목록을 내보내고 가져온다. JSON 가져오기는 영상별 설정을 복원하며 병렬로 메타데이터를 읽는다. | 가져오기 진행, 실패 항목, 원래 설정 보존을 유지한다. |
| F12 | Chrome 확장 수신 | 확장이 전송한 YouTube 탭 URL을 수신해 목록에 추가한다. | 현재 확장 프로토콜과 포트 호환성을 유지한다. P9 전에는 Chrome 프로필 직접 읽기를 추가하지 않는다. |
| F13 | 포함 도구·PO Token | 앱이 시작할 때 PO Token 공급자를 로컬에서 시작하고, 실패 시 플러그인 없는 안전한 yt-dlp 경로로 처리한다. | 도구를 사용자 AppData에 설치하지 않고, 도구 상태와 오류를 진단 가능하게 남긴다. |
| F14 | 업데이트·정보 | 앱/도구 버전 확인과 사용자 안내를 제공한다. | 네트워크 실패가 다운로드 화면 전체를 막지 않는다. |

## 데이터·호환성 원칙

1. 기존 사용자 설정의 의미와 기본값을 유지한다: `Path`, `IsTypeVideo`, `SubType`, `FileNameTemplate`, `GPUAccelerator`, `AudioBitrate`, `MaxConcurrentDownloads`.
2. JSON 내보내기 형식은 기존 `ExportVideoData`와 호환되어야 한다. 형식 변경이 필요하면 읽기는 구버전과 신버전을 모두 지원한다.
3. 영상 식별자는 YouTube ID를 기준으로 중복을 판단한다. 표시용 제목은 식별자로 사용하지 않는다.
4. 썸네일·메타데이터·자막·다운로드·병합은 UI 스레드를 점유하지 않는다.
5. 실행 파일 인접 도구는 읽기/실행만 전제한다. 설치 폴더가 쓰기 금지여도 앱의 기본 기능은 동작해야 한다.
6. 로컬 PO Token 공급자는 loopback 주소만 사용하며 앱 종료 시 중지한다.

## 단계별 설계 경계

| 단계 | 허용되는 변경 | 금지되는 변경 |
| --- | --- | --- |
| P1 | 기준 문서와 수동 검증 목록 | 제품 코드·동작 변경, WPF 프로젝트 생성 |
| P2 | UI와 무관한 공통 계약/서비스 분리 | WinForms 기준 기능 제거, 사용자 설정 형식 단절 |
| P3~P9 | 별도 WPF 앱에서 기능을 단계적으로 구현 | WinForms 프로젝트를 WPF로 덮어쓰기 |
| P10 | 두 앱의 기능·성능·배포 검증 | 검증 없이 WinForms 배포 중단 |
| P11 | WPF 기본 배포 여부 결정 | 호환성 확인 전 강제 전환 |

## P1 완료 기준

- 이 문서, 화면/UX 목록, 수동 검증 목록이 저장소에 있다.
- 이후 단계는 이 문서의 F01~F14를 회귀 기준으로 사용한다.
- WinForms 런타임 동작에는 변경이 없다.
